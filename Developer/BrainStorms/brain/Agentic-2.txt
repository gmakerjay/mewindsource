# q_learning.py

อันนี้คือ:

> Monte Carlo episodic RL approximation

คุณทำ:

```python
G_t = reward * (gamma ** steps_from_end)
```

แล้ว update:

```python
new_q = current_q + alpha * (G_t - current_q)
```

นี่คือ:

* Temporal Difference-ish update
* Monte Carlo return approximation

# จุดอันตราย / ปัญหาเชิงระบบ

อันนี้สำคัญมาก

---

# 1. State Representation ยัง “ตื้น”

ตอนนี้ state mainly คือ:

* LP
* board
* threat
* goals

แต่ยังขาด:

* chain context
* hidden information modeling
* probabilistic hand reading
* turn tempo
* summon commitment depth

ผลคือ:
Agent ยัง “ไม่เข้าใจเกม”
แต่ “จดจำ pattern”

---

# 2. Q-learning ยังไม่ใช่ True RL

ตอนนี้ Q-value key คือ:

```python
q_values[goal]
```

แปลว่า:
state abstraction กว้างมาก

ปัจจุบัน:

* action-value ไม่ละเอียด
* ไม่มี proper state-action tuple
* ไม่มี transition graph

มันเลยใกล้:

> contextual reward weighting

มากกว่า RL เต็มตัว

---

# 3. Reward Leakage

คุณใช้:

* LP difference
* outcome
* turn count

ซึ่งดีระดับหนึ่ง

แต่เสี่ยง:

* greedy aggression
* short-term overfitting
* combo inflation

แม้คุณมี anti-inflation แล้วก็ตาม

---

# 4. Registry Inflation Problem

แม้มี hard cap 8

แต่ system ยัง bias ไปทาง:
“card ที่ถูกเล่นบ่อย”

ไม่ใช่:
“card ที่ optimal จริง”

---

# 5. ไม่มี Exploration Strategy จริง

ยังไม่เห็น:

* epsilon-greedy
* UCB
* entropy exploration

ผลคือ:
Agent จะ converge เร็วเกิน
แล้วติด local optimum

---

# 6. Opponent Modeling ยัง Global

ยังไม่มี:

* matchup clustering
* archetype embeddings
* deck fingerprinting

ตอนนี้จำเป็น:
“card danger memory”

แต่ยังไม่:
“meta understanding”

---

# 7. Concurrency Risk

มี lock เยอะมาก

```csharp
_staticLock
```

แต่ยังมีจุดเสี่ยง:

* LP monitor thread
* file writes
* registry merge

โดยเฉพาะ:

* multiple duel instances
* parallel training

---

# 8. decisions.jsonl ยังไม่ใช่ Canonical Replay

ตอนนี้ log เป็น:

* flattened snapshots

แต่ยังไม่ใช่:

* full transition graph
* chain resolution trace
* causal replay

ซึ่งจำเป็นถ้าจะไป:

* imitation learning
* transformer replay
* sequence models

# ปัญหาที่จะเกิดแน่ ๆ ถ้าเปิด 20 จอ

---

# 1. Registry Corruption

ตัวอย่าง:

จอ 1:

```text
priority = 5 → 6
```

จอ 2:

```text
priority = 5 → 4
```

ทั้งคู่ write พร้อมกัน

ผล:

* overwrite กัน
* json เสีย
* learning หาย
* partial write

---

# 2. Learning Pollution

ถ้า bot เล่นมั่ว:

* bad opening
* brick hand
* RNG lose

แล้วคุณ reward/punish ตรง ๆ

จะเกิด:

> catastrophic heuristic drift

เช่น:

* good starter ถูกลด priority
* bad extender ถูก boost

เพราะ variance สูง

---

# 3. Infinite Self-Reinforcing Meta

Bot A:

* เล่นแปลก

Bot B:

* เรียนรู้รับมือ style แปลกนั้น

สุดท้าย:

* meta collapse
* overfit self-play

แต่แพ้คนจริง

นี่คือ classic self-play trap

---

# 4. LP=0 Detection ยังไม่ Atomic

ตอนนี้:

```csharp
MonitorLP()
```

thread polling ทุก 200ms

ปัญหา:

* duel reset ก่อน save เสร็จ
* match ใหม่เริ่ม
* state overwrite
* learning applied ซ้ำ

ถ้าเปิดหลายจอ โอกาสสูงมาก

---

# 5. Hot Deploy Race

ตอนนี้:

* save registry
* bot อื่น load registry

พร้อมกัน

ผล:

* half-written registry
* deserialize fail
* stale memory
* old cache
